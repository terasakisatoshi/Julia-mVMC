# L128 GPU speedup target: RTX3060 measurements

## Measured scope

The target was20× versus single-thread Julia CPU. The verified two-device result
is **13.98×**, so the20× target remains unfulfilled (issue#81 stays open).
These measurements evaluate identical fixed configurations, energy,256 one-body
and768 direct two-body Greens, and772 analytic parameter derivatives. They do not
measure complete optimization/PhysCal runs, compilation, input/model construction,
initialization, thermalization, SR updates, or final output copies.

| Devices | Walkers | CPU wall median | GPU wall median | CPU/GPU ratio |
|---|---:|---:|---:|---:|
| GPU1 |256|1.863790226s|0.289612141s|6.44×|
| GPU0+GPU1 |1024|8.158815728s|0.583759418s|13.98×|

Five warmed repetitions report synchronized min/median/max in the accompanying
text files. Ratios use medians, not selected extreme timings. The single-device
case uses configurations after12 one-proposal sampling calls; the two-device case
uses the initial fixed batch. Each CPU comparison uses exactly that run's GPU
configurations and quantities. These rows therefore do not measure the speedup
from adding a second GPU to the same batch. The two-device wall time includes
worker dispatch and synchronization; persistent workers each own512 walkers.

## Adopted changes and transfers

The real Pfaffian assigns columns to warps, preserves pivot/product order, and
uses explicit round-to-nearest multiply/add/divide operations. Slater updates
use C's four spin-block expressions directly, with resident parameter indices,
signs and rotation coefficients. Large inverse batches use cached device pointer
tables for cuBLAS LU/inversion and enforce skew symmetry before use.

Only unoccupied Slater columns need batched GEMM; occupied columns satisfy
`A^-1*S_occ=-I`. Ordinary operators evaluate independently against read-only
virtual moves, followed by Hamiltonian addition in original input order.
Large analytic derivatives use resident CSC coefficients and predecoded row
coordinates, directly contracting inverse cofactors. Singular projection sectors
retain exact minor evaluation with disjoint fallback workspaces.

The single-device warmed sampling+observable+derivative CUPTI application range
records **zero memory-copy records**, including device-to-device copies. Profiler
bookkeeping before its initial synchronization is excluded using the same range
as CUDA's display. Two-device results are copied only after timing; their worker
protocol does not transfer configurations or intermediate results between GPUs.
Setup still constructs and uploads the dense Slater basis, so startup cost and
memory capacity remain relevant. Each production optimizer/PhysCal runner uses
one device; the two-device script shards only the fixed measurement workload.

## Numerical evidence

All elementwise comparisons retain `atol=rtol=1e-9`:

| Devices/batch | Maximum absolute observable error | Maximum absolute derivative error |
|---|---:|---:|
| GPU1/256 |8.591883e-11|1.059147e-11|
| GPU0+GPU1/1024 |1.929700e-6|6.967457e-8|

The two-device large absolute errors occur with very large quantities, including
an energy of approximately-1.43549e7; every relative/absolute elementwise gate
passes, with zero mismatched observables and derivatives. Results are compared
numerically, not bitwise.

A failing prototype exposed configuration29's projected-sum cancellation number
`sum(abs(weight*Pf))/abs(sum(weight*Pf))=2.521717e6`, with individual matrix
conditions85.6–3996.5. Basis GEMV first differed from CPU Slater elements by
4.44e-16. Separately, on identical CPU matrix inputs, implicit GPU multiply/add
contraction changed per-sector Pfaffians by up to2.19e-13 relatively and the
projected overlap by1.67854e-8. Direct Slater assembly and explicitly rounded
Pfaffian/weight operations remove these divergences in this Linux case; the
existing1e-9 projected gate passes. Neither seeds nor numerical thresholds were
changed. The regression preserves that strongly cancelling configuration.

The final GPU suite passed **3957 assertions** on GPU0. CPU-only verification
and Linux/macOS CI from the initial GPU PR remain recorded
in the earlier report. The follow-up GPU suite additionally checks64/128-site
shared20-step trajectories, exact future UInt32 words/configurations, batched
inverse residuals/singular flags, occupied/unoccupied transforms, all ordinary
operator coincidences and singular-sector fused derivatives. Tiny raw parameters
use independent C four-block closed forms, distinguished from historical Julia
orbital-value filtering.

## Reproduction

```sh
JULIA_MVMC_GPU_DEVICE=0 julia +1.13.1 --project=test/gpu test/gpu/runtests.jl
JULIA_MVMC_GPU_DEVICE=1 JULIA_MVMC_GPU_WALKERS=256 \
JULIA_MVMC_GPU_BENCH_STEPS=1 JULIA_MVMC_GPU_PROFILE=1 \
julia +1.13.1 --project=test/gpu test/gpu/benchmark.jl \
  benchmark/cuda/inputs/hubbard_chain_L128/namelist.def
JULIA_MVMC_GPU_WALKERS=1024 julia +1.13.1 --threads=2 --project=test/gpu \
  test/gpu/benchmark_multi_gpu.jl
```

Shared-memory Pfaffian prototypes, inverse Utu2 reuse and overlapping independent
LU/Pfaffian streams were measured but did not improve the adopted path enough.
They are not included in production. The20× target must not be inferred from
primitive timings or from a relaxed numerical check.
